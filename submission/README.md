# LH2 흡입배관 대리모델과 설계 후보

## 1. 자료 구성

LH2 흡입배관의 열침입·압력 손실·외경을 비교하고 설계 후보를 찾았다. 노트북에 설명·표·그림과 실행 출력을 저장해 두어 실행 없이 읽을 수 있음. 이번 재검증 반영본의 Run All은 저장된 결과만 읽으며 재학습·최적화·최종 테스트 평가를 실행하지 않는다.

| 경로 | 내용 |
|---|---|
| `LH2_core.ipynb` | 물리식 설명, 기존 학습·최종 테스트·최적화 결과 조회 |
| `data/dataset_ai_10k.csv` | 정답이 있는 1D 솔버 출력 10,000개 |
| `results/` | 원본 `outputs/full10k/report/`의 표·그림과 결과 설명 |
| `results/reproduction/` | 원본 manifest·분할·부분표본 ID, 정확한 커널, 실행 환경, 재현 비교표 |
| `full_pipeline/` | 원본 코드·설정·문서·테스트의 사본과 제출본 검증 테스트 |
| `full_pipeline/ann_reference.py` | 깊은 MLP를 개발 자료의 같은 5-fold에서 비교하는 DNN 실행 코드 |
| `results/T1b_dnn_cv.csv` | DNN의 타깃별 CV 지표, 실제 후보 수, 선정 설정과 실행 시간 |
| `results/T1_with_dnn.csv` | 기존 T1의 수치를 유지하고 DNN 행만 추가한 비교표 |

외경과 강체 압력은 식으로 계산한다. 수력 압력은 강체 압력의 1.8배를 기본으로 쓰고 GPR 비율 보정과 비교한다. AI의 핵심 역할은 열적 압력 손실 `dp_thermal` 예측이다. 열침입은 물리식과 비교한다. 원본이 두 출력 모두 GPR을 선정했으며, 저장된 재현 평가와 최적화 기록도 같은 모델 구성이다.

## 2. 노트북 실행

노트북 실행 환경은 제출 폴더에서 아래 순서로 준비한다. JupyterLab을 열고 `LH2_core.ipynb`에서 커널을 선택한 뒤 Restart Kernel and Run All Cells를 실행한다. 패키지 설치 시간은 노트북 측정 시간에서 제외함.

```bash
python3.10 -m venv .venv
source .venv/bin/activate
pip install -r results/reproduction/requirements-notebook.txt
pip install jupyterlab
python -m ipykernel install --prefix .venv --name lh2 --display-name 'LH2 Python'
jupyter lab LH2_core.ipynb
```

기존 재현 실행 시간과 원본 대비 차이는 아래 실측 표에 기록했다. 이번 반영본은 이 기록을 읽기만 한다. 기존 재현에서는 학습된 커널을 전체 정밀도로 고정하고 GPR 3,000개 부분표본의 ID·순서를 재사용했다. MLP는 원본 선정 설정으로 개발 데이터 8,000개를 학습했다. 튜닝과 커널 최적화를 생략했으며, 원본 `finalize`는 다시 실행하지 않았다. 당시 최종 테스트는 고정 설정의 재현 비교에만 사용했다.

기존 재현 노트북의 실측 실행 시간은 24.26초이다(커널 시작을 포함한 시간은 `results/reproduction/package_validation.json` 참조). 최종 테스트 2,000개에서의 차이는 아래 표에 정리했다. 차이는 노트북 − 원본이며 MAPE 차이 단위는 %p이다.

| 출력 | 모델 | ΔR² | ΔRMSE | ΔMAPE (%p) |
|---|---|---:|---:|---:|
| 열침입 [W] | GPR | 4.330e-15 | -4.565e-10 | 1.417e-09 |
| 열침입 [W] | MLP | 0.000e+00 | 5.551e-17 | 0.000e+00 |
| 열적 압력 [Pa] | GPR | 1.917e-13 | -1.185e-07 | -3.094e-10 |
| 열적 압력 [Pa] | MLP | -1.110e-16 | 0.000e+00 | 0.000e+00 |

GPR의 미세한 차이는 커널 복원과 부동소수점 연산 경로의 차이로 추정한다. MLP는 표시 정밀도에서 일치한다. 수력 보정의 false safe/unsafe 개수와 S1 A·B·C의 설계값도 원본과 일치하며, A·C 단열 두께의 차이는 4×10⁻¹⁵ mm 미만이다.

원본 코드를 복사한 뒤 제출본의 주석과 설명 문구를 다듬었다. 제출본의 파일 무결성과 실행 출력을 확인하는 테스트만 추가했다. 노트북용 데이터는 `data/`에, 원본 코드의 테스트·벤치마크용 입력 사본은 `full_pipeline/data/`에 담았다. 가상환경·캐시·기존 outputs·Git 및 개인 설정 폴더는 제외했다.

## 3. 전체 파이프라인 실행

전체 재현은 약 3시간이며 아래 명령으로 실행한다. `run_full10k.sh`는 `full_pipeline/.venv`를 사용하므로 별도 환경을 만든다. 실행은 백그라운드로 진행되며 `run.log`에서 확인할 수 있다. 새 출력 폴더에 실행하며 제출된 결과는 덮어쓰지 않음.

```bash
cd full_pipeline
python3.10 -m venv .venv
.venv/bin/pip install -r ../results/reproduction/requirements-notebook.txt
.venv/bin/python -m unittest discover -s tests -v
bash run_full10k.sh ../data/dataset_ai_10k.csv --out outputs/reproduction
# 진행 확인
tail -f outputs/reproduction/run.log
```

전체 재현에는 개발 데이터의 모델 비교·튜닝·학습 곡선, 선정 완료 후 최종 테스트 1회, S1–S3 최적화가 포함된다. `finalize` 시작 기록이 있으면 중단·실패했어도 다시 실행하지 않는다. 재개할 때는 같은 명령과 같은 출력 폴더를 사용한다. 다항 Ridge·RF·MLP는 각각 출력별 50후보, GPR은 각각 6후보 전수 탐색을 했다. 선형과 물리식은 튜닝하지 않았다. F2는 개발 데이터 안의 고정 검증 RMSE이다. 원본의 전체 실행은 약 2.87시간이었다. 파일럿 비교 보조표는 `results/`의 사본으로 제공하며, 파일럿 outputs를 제외한 전체 재현에서는 해당 보조표가 미제공으로 표시된다.

복사본의 `requirements-tested.txt`는 원본 문서에 남아 있는 별도 환경 기록이다. 이 제출본의 실측 환경은 `results/reproduction/environment.json`과 `requirements-notebook.txt`를 기준으로 한다.

## 4. 결과와 한계

최종 테스트 2,000개의 원본 수치이다. RMSE 단위는 열침입 W, 열적 압력 Pa이다.

| 출력 | 모델 | R² | RMSE | MAPE (%) |
|---|---|---:|---:|---:|
| 열침입 | GPR | 0.999999991 | 0.001965605 | 0.001087416 |
| 열침입 | MLP | 0.999490291 | 0.467578881 | 0.871363695 |
| 열적 압력 | GPR | 0.999981371 | 23.050065902 | 0.209912607 |
| 열적 압력 | MLP | 0.995340812 | 364.533115757 | 1.921484304 |

수력 보정은 같은 최종 테스트에서 전체 압력 오차와 제약 판정을 개선했다. 경계 구간은 실제 전체 압력 38.3–58.3 kPa의 134개이며, 안전 제약은 48.3 kPa 이하이다. false safe는 실제 초과를 안전으로, false unsafe는 실제 안전을 초과로 예측한 개수이다.

| 수력 보정 | 전체 압력 MAPE (%) | 경계 MAPE (%) | false safe | false unsafe |
|---|---:|---:|---:|---:|
| 1.8 고정 | 0.687533271 | 0.951264697 | 1 | 4 |
| GPR 비율 | 0.073793844 | 0.089401457 | 0 | 0 |

원본 수치는 `results/T_final_test_metrics.csv`, `results/T_hydraulic_effect.csv`에 있다. 재현 차이는 `results/reproduction/notebook_*comparison.csv`에 따로 저장했다. 원본 경고는 `results/T_warnings.csv`에 보존함.

1D 재검증 결과는 `results/T4_reverification.csv`와 `results/F_T4_reverification.png`에 있다.

| 방식 | Q_leak 평균 / 최대 오차 (%) | dp_thermal 평균 / 최대 오차 (%) | dp_design 평균 / 최대 오차 (%) | 판정 일치 |
|---|---:|---:|---:|---:|
| const | 0.001447 / 0.005976 | 0.154706 / 0.906288 | 0.931966 / 1.469167 | 27/27 |
| gpr | 0.001460 / 0.005976 | 0.152522 / 0.892604 | 0.045181 / 0.170341 | 24/27 |

54개 전체 출력의 status는 모두 converged이며, 각 방식 27점의 세 출력 모두 최대 절대오차 5% 이내이다. 오차는 100×(예측/솔버−1), 위 평균·최대는 절대오차이다.
const의 전체 압력 평균 부호 있는 오차는 +0.931966%, 수력 성분은 +1.015842%(평균 +238.860 Pa)이다. 솔버 수력/강체 비율은 1.773353–1.796532(평균 1.781924)로 1.8보다 작아 보수적인 과대평가가 판정 전부 일치에 기여했다. 이는 항상 안전하다는 보장은 아니다.
GPR의 전체 압력 평균 부호 있는 오차는 −0.030725%이며, V003(S1/C), V012(S2/C), V021(S3/C)는 안전으로 예측했지만 솔버에서 각각 6.1, 18.3, 1.0 Pa 초과했다. 상세 값은 results/T4_mismatches.csv에 있다.
일정 비율의 제약 여유 등은 재검증 결과를 보고 한 사후 제안이며 적용·검증하지 않았다. 제약 48,300 Pa와 기존 최적화 결과는 유지했고 학습·최적화·최종 테스트·솔버를 다시 실행하지 않았다.
T4는 저장소의 compare 명령으로 전체 출력에서 계산했으며 교차 확인용 T4의 54행·모든 공통 열과 일치한다(최대 수치 차이 0). 이 결과는 해당 54점의 1D 재검증이며 실험 검증이나 전체 설계 공간의 안전성 보장은 아니다.

데이터는 실험값이 아닌 1D 솔버 출력임. GPR은 계산량 때문에 개발 데이터의 3,000개 부분표본을 사용했다. 대리모델 Pareto와 A·B·C는 설계 후보이며, 1D 재검증 결과는 별도이다. 물리 특성 유무 비교표는 파일럿 개발 데이터의 결과이다. 1만 개 데이터에서 특성을 제거한 모델을 다시 학습한 비교가 아니다.

문제 정의, 실험 설계(데이터 분할·평가 기준·비교 모델·하이브리드 구조·사전 설정), 결과 검증과 해석은 팀이 수행했습니다.일부 파일의 구현에는 AI 코딩 도구(Codex)의 도움을 받았습니다: [artifact_state.py, full10k_runner.py(실행상태 관리 파트)]


## 5. 추가 분석

보수 판정은 재검증 결과를 보고 한 사후 분석이다. 열 성분만 `σ[Pa] ≈ ln(10)×예측[Pa]×σ[log10]`로 환산해 2σ를 더하자 GPR C점 3개가 모두 제외되어 판정 일치가 24/27→27/27이었다. const는 안전한 4점을 추가 제외해 27/27→23/27이며, 재최적화는 하지 않았다.

모델 해석에서는 표준화 입력의 길이척도가 클수록 그 입력의 영향이 작다(상관·물리 파생 특성에 유의). 개발 배경 200개의 PDP에서 t_ins 증가 시 Q_leak 41.440→7.057 W, k_MLI 증가 시 0.589→53.678 W로 기대 경향을 확인했다.

외삽 시험에서는 개발 자료 D < 40 mm에서 학습하고 범위 안 검증 1,179개·밖 2,108개로 평가했다. dp_thermal MAPE는 GPR 0.284823→1.240804%, MLP 2.917993→11.853203%; GPR 3,000개·MLP 4,713개 학습, 최종 설정·학습된 커널 고정, 새 튜닝 0회다. 커널 선정에는 전체 개발 자료가 쓰였으므로 조건부 진단이다.

새 표·그림은 `outputs/full10k/analysis/`에만 저장했다. 노트북의 추가 분석 절은 제출 폴더의 상위 저장소에서 이 경로를 읽으므로 해당 폴더를 함께 유지해야 한다. Run All은 저장 결과만 읽으며 기존 학습·최적화·최종 테스트·솔버를 실행하지 않는다. 분석 스크립트는 루트의 `analysis_conservative.py`, `analysis_interpretation.py`, `analysis_extrapolation.py`이며, 마지막 스크립트만 분석용 모델을 새로 학습한다.
